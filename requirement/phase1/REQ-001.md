# REQ-001: Bamboo Mint — Standalone Fcitx5 Input Method Addon

**Status:** Implemented  
**Branch:** `dev`  
**Date:** 2026-08-16

---

## 1. Objective

Create a **standalone** fcitx5 input-method addon named **Bamboo Mint** (`bamboomint`) derived from the existing `bamboo` engine. It must coexist with the original `bamboo` addon in the same fcitx5 session, appear as a separate entry in the tray, and allow switching between Vietnamese (`bamboo` / `mint`), Japanese (`mozc`), and Chinese (`pinyin`, `cangjie`) input methods.

---

## 2. Environment

| Component | Version / Path |
|-----------|---------------|
| OS | Linux Mint (Ubuntu-based) |
| fcitx5 | `5.1.7` |
| CMake | `3.28.3` |
| Go | `1.22.2` |

| Dev packages | `libfcitx5core-dev`, `libfcitx5config-dev`, `libfcitx5utils-dev`, `fcitx5-modules-dev`, `extra-cmake-modules` |

> **Note:** The upstream project requires fcitx5 `5.1.13`, but the system only has `5.1.7`. The version requirement was lowered locally.

## 3. Step-by-Step Implementation

### 3.1. Clone missing submodule

The Go core library (`bamboo-core`) is a submodule and was not present after a fresh clone.

```bash
git submodule update --init --recursive
```

**Result:** `bamboo/bamboo-core/` populated with `go.mod` and Go sources.

---

### 3.2. Fix CMake version compatibility

**File:** `CMakeLists.txt`

- Change `REQUIRED_FCITX_VERSION` from `5.1.13` → `5.1.7`.
- Add a **fallback** `add_fcitx5_addon` macro because fcitx5 `5.1.7` dev packages do not export this function (it was internal in newer upstream versions).

```cmake
if (NOT COMMAND add_fcitx5_addon)
  set(FCITX_ADDON_CMAKE_LIBRARY_TYPE MODULE)
  function(add_fcitx5_addon target_name)
    cmake_parse_arguments(ARG "" "" "" ${ARGN})
    set(srcs ${ARG_UNPARSED_ARGUMENTS})
    add_library(${target_name} ${FCITX_ADDON_CMAKE_LIBRARY_TYPE} ${srcs})
    set_target_properties(${target_name} PROPERTIES FCITX_ADDON TRUE)
  endfunction()
endif()
```

---

### 3.3. Fix C++ build errors against fcitx5 5.1.7

**File:** `src/bamboo.cpp`

| Upstream API (5.1.13+) | System API (5.1.7) |
|--------------------------|--------------------|
| `#include <fcitx-utils/standardpaths.h>` | `#include <fcitx-utils/standardpath.h>` |
| `StandardPaths::global().open(...)` | `StandardPath::global().open(..., O_RDONLY)` |
| `StandardPathsType::PkgData` | `StandardPath::Type::PkgData` |
| `path.starts_with(...)` | `stringutils::startsWith(path, ...)` |
| `FCITX_ADDON_FACTORY_V2(bamboo, fcitx::BambooFactory)` | `FCITX_ADDON_FACTORY(fcitx::BambooFactory)` |

These changes were required **for the original engine too**, otherwise `src/bamboo.cpp` would fail to compile.

---

### 3.4. Create the new `bamboomint` engine

A new directory `src/mint/` was created containing a fully-renamed copy of the bamboo engine.

#### New files created:

| File | Purpose |
|------|---------|
| `src/mint/bamboomint.cpp` | Main engine implementation (renamed from `bamboo.cpp`) |
| `src/mint/bamboomint.h` | Header with renamed classes (`BambooMintEngine`, `BambooMintState`, `BambooMintFactory`) |
| `src/mint/bamboomintconfig.h` | Config structures renamed to `BambooMintConfig`, `BambooMintMacroTable`, etc. |
| `src/mint/CMakeLists.txt` | Build rules for `libbamboomint.so` |
| `src/mint/mint-addon.conf.in.in` | Addon metadata (name = "Bamboo Mint Wrapper For Fcitx", library = `libbamboomint`) |
| `src/mint/mint.conf.in` | Input-method entry (name = "Bamboo Mint", icon = `fcitx_bamboo_mint`, lang = `vi`) |

#### Key renames applied:

- `BambooEngine` → `BambooMintEngine`
- `BambooState` → `BambooMintState`
- `BambooFactory` → `BambooMintFactory`
- `BambooConfig` → `BambooMintConfig`
- `BambooCustomKeymap` → `BambooMintCustomKeymap`
- `BambooMacroTable` → `BambooMintMacroTable`
- `BambooKeymap` → `BambooMintKeymap`
- Action prefixes: `bamboo-input-method-` → `bamboomint-input-method-`, etc.
- Config paths: `conf/bamboo.conf` → `conf/bamboomint.conf`, `conf/bamboomint-custom-keymap.conf`, `conf/bamboomint-macro-<IM>.conf`
- Gettext domain: `fcitx5-bamboo` → `fcitx5-bamboo-mint`
- Addon factory macro: `FCITX_ADDON_FACTORY(fcitx::BambooMintFactory)`

### 3.5. Wire the new subdirectory into the build

**File:** `src/CMakeLists.txt`

Added **before** the original `bamboo` target:

```cmake
add_subdirectory(mint)
```

This ensures `bamboomint` is built alongside the original `bamboo`.

### 3.6. Create a distinct icon

**New files:**
- `data/scalable/apps/org.fcitx.Fcitx5.fcitx_bamboo_mint.svg` (copied from original and recolored green `#16a34a`)
- `data/scalable/apps/fcitx_bamboo_mint.svg` → symlink to the above

This lets the tray distinguish **Bamboo Mint** (green) from **Bamboo** (red).

### 3.7. Build

```bash
mkdir -p build && cd build
cmake ..
make -j4
```

**Outputs:**
- `build/src/libbamboo.so`
- `build/src/mint/libbamboomint.so`
- `build/src/bamboo.conf`
- `build/src/mint/mint.conf`
- `build/src/mint/mint-addon.conf`

---

### 3.8. System-wide installation

Because the running fcitx5 reads from `/usr/share/fcitx5/` (not `/usr/local/`), files were copied to the system directories:

```bash
sudo make install                              # installs to /usr/local/ (optional)
sudo cp /usr/local/lib/fcitx5/libbamboomint.so /usr/lib/x86_64-linux-gnu/fcitx5/
sudo cp /usr/local/share/fcitx5/addon/bamboomint.conf /usr/share/fcitx5/addon/
sudo cp /usr/local/share/fcitx5/inputmethod/mint.conf /usr/share/fcitx5/inputmethod/
sudo cp /usr/local/share/icons/hicolor/scalable/apps/fcitx_bamboo_mint.svg /usr/share/icons/hicolor/scalable/apps/
```

> **Note:** `libbamboo.so` and its config files were also installed, but they already existed on the system. Only `bamboomint` files were truly new.

---

### 3.9. Register `mint` in the fcitx5 user profile

**File:** `~/.config/fcitx5/profile`

Added `mint` to the `[Groups/0]` input-method list so it appears in the tray switcher:

```ini
[Groups/0]
Name=Default
Default Layout=us
DefaultIM=bamboo

[Groups/0/Items/0]
Name=keyboard-us

[Groups/0/Items/1]
Name=bamboo

[Groups/0/Items/2]
Name=mint       ; <-- Bamboo Mint

[Groups/0/Items/3]
Name=mozc       ; Japanese

[Groups/0/Items/4]
Name=pinyin     ; Chinese (Pinyin)

[Groups/0/Items/5]
Name=cangjie    ; Chinese (Cangjie)

[GroupOrder]
0=Default
```

After editing, reload fcitx5:

```bash
fcitx5-remote -r
```

### 3.10. Fix Zed / clangd diagnostics (false red squiggles)

**Problem:** After the build succeeded, Zed still showed red error squiggles on `src/bamboo.cpp` and `src/mint/bamboomint.cpp`. Examples:

- `'bamboo-core.h' file not found`
- `No type named 'string_view' in namespace 'std'`
- `Unknown type name 'BambooMacroTable'`
- `Expected expression` on `_()` macro calls

**Root cause:** `clangd` (the language server used by Zed) only sees files under the project root by default. It does **not** know that:

1. `bamboo-core.h` is generated into `build/bamboo/` during the Go build step.
2. The correct compile flags are `-std=c++17`, include paths to `/usr/include/Fcitx5/{Core,Config,Utils}`, and the `FCITX_GETTEXT_DOMAIN` macro.

CMake passes all of this to `gcc`, so `make` succeeds, but `clangd` runs without that context unless we tell it explicitly.

**Solution:**

1. **Regenerate compile database with CMake:**

```bash
cd build
cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON ..
```

2. **Create a symlink at the repo root:**

```bash
cd /home/lmo1720/Fcitx-Bamboo-Mint/fcitx5-bamboo
ln -sf build/compile_commands.json compile_commands.json
```

3. **Create `.clangd` at the repo root** with the flags `clangd` needs:

```yaml
CompileFlags:
  Add:
    - -std=c++17
    - -I/home/lmo1720/Fcitx-Bamboo-Mint/fcitx5-bamboo/build/bamboo
    - -I/usr/include/Fcitx5/Core
    - -I/usr/include/Fcitx5/Config
    - -I/usr/include/Fcitx5/Utils
    - -DFCITX_GETTEXT_DOMAIN="fcitx5-bamboo"
    - -DFCITX_INSTALL_LOCALEDIR="/usr/local/share/locale"
    - -D_GNU_SOURCE
```

> Replace `/home/lmo1720/Fcitx-Bamboo-Mint/fcitx5-bamboo` with your actual project path if different.

4. **Whitelist the new files in `.gitignore`:**

The repo's `.gitignore` contains `.*` which ignores everything starting with a dot. Add exceptions:

```gitignore
.*
!.clangd
!compile_commands.json
!.git*
```

**Result:** Diagnostics in Zed now report `File doesn't have errors or warnings` for all source and header files.

## 7. Known Issues / Next Steps

1. **Zed editor runtime issue:** Bamboo Mint works in Text Editor but exhibits typing issues inside Zed itself. This is **not addressed** in this requirement; deferred for future investigation.
   > **Note:** The Zed *diagnostics* (red squiggles) issue was fixed in step 3.10. Only the actual *typing behaviour* inside Zed remains unresolved.
2. **Locale files:** The new gettext domain `fcitx5-bamboo-mint` has no `.po` translations yet; it falls back to English for config UI labels.
3. **Packaging:** Current installation uses manual `sudo cp`. A proper `make install` with correct `CMAKE_INSTALL_PREFIX=/usr` would be cleaner for distro packaging.
