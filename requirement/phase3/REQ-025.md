# REQ-025: Chú thích file `bamboo.go` — Engine chính xử lý tiếng Việt

## 1. Mục đích

File `bamboo/bamboo-core/bamboo.go` là **engine cốt lõi** của bộ gõ tiếng Việt. Nó quản lý toàn bộ trạng thái bàn phím (composition), xử lý từng phím người dùng nhấn, và biến đổi chuỗi phím thô thành chuỗi tiếng Việt có dấu.

File này định nghĩa:
- Các chế độ hoạt động (`Mode`): tiếng Việt, tiếng Anh, không dấu...
- Các cờ cấu hình (`Flags`): tự do đặt dấu thanh, kiểu chuẩn, tự sửa...
- Cấu trúc `Transformation` — đơn vị biến đổi cơ bản
- Interface `IEngine` — giao diện engine để C++ gọi qua CGO
- Struct `BambooEngine` — triển khai engine

## 2. Phân tích cấu trúc

### 2.1. Các hằng số Mode

```go
type Mode uint

const (
    VietnameseMode  Mode = 1 << iota   // Chế độ tiếng Việt (dùng để Flatten ra chuỗi cuối)
    EnglishMode                         // Chế độ tiếng Anh — phím không qua xử lý tiếng Việt
    ToneLess                            // Bỏ dấu thanh khi Flatten
    MarkLess                            // Bỏ dấu phụ (móc, râu, trăng...) khi Flatten
    LowerCase                           // Ép về chữ thường khi Flatten
    FullText                            // Lấy toàn bộ composition (không chỉ âm tiết cuối)
    PunctuationMode                     // Xử lý dấu câu đặc biệt
    InReverseOrder                      // Thêm phím vào đầu composition (cho kiểu gõ đảo ngược)
)
```

**Ý nghĩa:** `Mode` dùng khi gọi `Flatten()` để quyết định output dạng gì. Ví dụ `VietnameseMode` cho ra chuỗi tiếng Việt đầy đủ, còn `ToneLess|MarkLess` cho ra chuỗi không dấu.

### 2.2. Các hằng số Flags (cấu hình engine)

```go
const (
    EfreeToneMarking    uint = 1 << iota   // Cho phép đặt dấu thanh tự do (không cần đúng quy tắc)
    EstdToneStyle                           // Kiểu dấu thanh chuẩn (ư, ơ, v.v.)
    EautoCorrectEnabled                     // Bật tự động sửa chính tả
    EstdFlags = EfreeToneMarking | EstdToneStyle | EautoCorrectEnabled
)
```

**Ý nghĩa:** `Flags` khác `Mode` — `Flags` là cấu hình engine (bật/tắt tính năng), còn `Mode` là yêu cầu output. `Flags` được truyền vào khi `NewEngine()`.

### 2.3. Struct Transformation

```go
type Transformation struct {
    Rule        Rule            // Quy tắc áp dụng (APPENDING, MARK, TONE...)
    Target      *Transformation // Con trỏ tới transformation bị tác động (nếu là MARK/TONE)
    IsUpperCase bool            // Phím gốc có phải chữ hoa không
}
```

**Ý nghĩa:** Mỗi phím người dùng nhấn tạo ra một hoặc nhiều `Transformation`. Nếu là phím chữ cái thường, `Rule` thường là `APPENDING`. Nếu là phím s/x/f... thì `Rule` là `TONE`/`MARK`, và `Target` trỏ về chữ cái cần gạch/chữ cái đích.

### 2.4. Interface IEngine

```go
type IEngine interface {
    SetFlag(uint)
    GetInputMethod() InputMethod
    ProcessKey(rune, Mode)
    ProcessString(string, Mode)
    GetProcessedString(Mode) string
    IsValid(bool) bool
    CanProcessKey(rune) bool
    RemoveLastChar(bool)
    RestoreLastWord(bool)
    Reset()
}
```

**Ý nghĩa:** Đây là interface chuẩn để lớp C++ trong `src/mint/` gọi qua CGO. Mọi hàm đều có bản export trong `bamboo_utils.go` (qua `//export`).

### 2.5. Struct BambooEngine

```go
type BambooEngine struct {
    composition []*Transformation   // Danh sách các transformation đã nhập
    inputMethod InputMethod         // Kiểu gõ hiện tại (Telex...)
    flags       uint                // Cấu hình flags
}
```

**Ý nghĩa:** `composition` giữ toàn bộ lịch sử phím đã nhập. Đây chính là "bộ nhớ" của engine. Khi người dùng nhấn Backspace, ta xóa transformation cuối khỏi `composition`.

## 3. Phân tích từng hàm

### 3.1. `NewEngine(inputMethod InputMethod, flag uint) IEngine`

- **Input:** `inputMethod` — kiểu gõ đã parse; `flag` — cấu hình.
- **Output:** Con trỏ `*BambooEngine` (đóng gói trong `IEngine`).
- **Logic:** Khởi tạo engine với `composition` rỗng.

### 3.2. `GetInputMethod() / SetFlag(flag) / GetFlag(flag)`

- **Logic:** Getter/Setter cơ bản. C++ gọi qua CGO để biết kiểu gõ hiện tại.

### 3.3. `IsValid(inputIsFullComplete bool) bool`

- **Input:** `inputIsFullComplete` — nếu true thì kiểm tra cả âm tiết hoàn chỉnh.
- **Output:** `true` nếu âm tiết cuối hợp lệ tiếng Việt.
- **Logic:** Gọi `extractLastWord` để tách âm tiết cuối, rồi gọi `isValid()` kiểm tra.
- **Ví dụ:** `"nguyeenx"` → `false` (vì "nguyeenx" không hợp lệ); `"nguyen"` → `true`.

### 3.4. `GetProcessedString(mode Mode) string`

- **Input:** `mode` — yêu cầu định dạng output.
- **Output:** Chuỗi tiếng Việt đã xử lý.
- **Logic:**
  - Nếu `FullText`: Flatten toàn bộ `composition`.
  - Nếu `PunctuationMode`: Tách âm tiết cuối kèm dấu câu, Flatten.
  - Mặc định: Tách âm tiết cuối (qua `extractLastWord`), rồi Flatten.
- **Ý nghĩa:** Đây là hàm C++ gọi để lấy chuỗi hiển thị trên preedit.

### 3.5. `getApplicableRules(key rune) []Rule`

- **Input:** `key` — phím người dùng nhấn.
- **Output:** Danh sách các `Rule` trong kiểu gõ có `Key` khớp.
- **Logic:** Duyệt `e.inputMethod.Rules`, so sánh `Rule.Key == unicode.ToLower(key)`.
- **Ví dụ:** Kiểu Telex, nhấn `a` → tìm các rule có `Key == 'a'` (có thể là APPENDING_a, hoặc MARK_hoi nếu `a` đóng vai trò khác trong macro).

### 3.6. `findTargetByKey(composition, key) (*Transformation, Rule)`

- **Input:** `composition` hiện tại; `key` — phím mới.
- **Output:** (`target`, `rule`) — `target` là transformation bị tác động, `rule` là rule sẽ áp dụng.
- **Logic:** Gọi `findTarget()` (trong `bamboo_utils.go`) để tìm vị trí đặt dấu/thanh hợp lý nhất trong âm tiết.

### 3.7. `CanProcessKey(key rune) bool`

- **Input:** `key` — phím cần kiểm tra.
- **Output:** `true` nếu phím này thuộc bảng phím của kiểu gõ.
- **Logic:** Gọi `canProcessKey()` (trong `bamboo_utils.go`).
- **Ý nghĩa:** C++ gọi trước để quyết định có đưa phím vào engine hay xử lý như phím thường.

### 3.8. `generateTransformations(composition, lowerKey, isUpperCase) []*Transformation`

- **Input:** `composition` hiện tại; `lowerKey` — phím thường hóa; `isUpperCase` — phím gốc có hoa không.
- **Output:** Danh sách transformation mới cho phím này.
- **Logic:**
  1. Gọi `generateTransformations()` (hàm global trong `bamboo_utils.go`) để thử áp dụng các rule khả dụng.
  2. Nếu **không có rule nào áp dụng được** → tạo fallback `APPENDING` transformation.
  3. Kiểm tra shortcut `uwo+` (ví dụ: gõ `uơ` nhanh bằng cách nhấn `w` sau `uo`). Nếu đúng pattern `u[oơ]`, tạo virtual transformation thêm dấu móc.
  4. Cuối cùng, gọi `refreshLastToneTarget()` để điều chỉnh lại vị trí dấu thanh nếu cần (ví dụ: `chuyr` → `chuỷ` rồi `chuyrene` → `chuyển`, dấu thanh phải chuyển từ `y` sang `e`).
- **Ý nghĩa:** Đây là **hàm cốt lõi** nhất — nó quyết định mỗi phím tạo ra transformation gì.

### 3.9. `newComposition(composition, key, isUpperCase) []*Transformation`

- **Input:** `composition` hiện tại; `key`; `isUpperCase`.
- **Output:** `composition` mới sau khi xử lý phím.
- **Logic:**
  1. Tách `composition` thành `previousTransformations` (trước âm tiết cuối) và `lastSyllable`.
  2. Gọi `generateTransformations` trên `lastSyllable`.
  3. Nối lại: `previousTransformations + lastSyllable mới`.
- **Ý nghĩa:** Đảm bảo engine chỉ xử lý phím trên **âm tiết cuối**, không ảnh hưởng các âm tiết trước đó.

### 3.10. `applyUowShortcut(syllable) *Transformation`

- **Input:** Một âm tiết (slice transformations).
- **Output:** Virtual transformation nếu khớp shortcut `uơ/oơ`; `nil` nếu không.
- **Logic:**
  1. Flatten âm tiết dạng `ToneLess|LowerCase` → ví dụ `"uo"`.
  2. Kiểm tra regex `regUOhTail.MatchString(str)` (có kết thúc bằng `uo` hoặc `uơ`...).
  3. Nếu khớp, tìm target là chữ `u` hoặc `o` trong âm tiết, tạo virtual `MARK_HORN` transformation trỏ vào đó.
  4. Đặt `Key = rune(0)` để virtual rule không xuất hiện trong raw string.
- **Ý nghĩa:** Hỗ trợ kiểu gõ nhanh `uwo` → `ươ`, `uwow` → `ượ`...

### 3.11. `refreshLastToneTarget(syllable) []*Transformation`

- **Input:** Một âm tiết.
- **Output:** Các transformation bổ sung để điều chỉnh lại vị trí dấu thanh.
- **Logic:** Nếu `EfreeToneMarking` bật và âm tiết hợp lệ, gọi `refreshLastToneTarget()` global (trong `bamboo_utils.go`) để di chuyển dấu thanh sang vị trí đúng theo quy tắc mới.

## 4. Các hàm có side-effect (thay đổi trạng thái engine)

### 4.1. `ProcessString(str string, mode Mode)`

- **Input:** Chuỗi cần xử lý; `mode`.
- **Logic:** Lặp từng ký tự, gọi `ProcessKey`. Dùng khi paste chuỗi hoặc khôi phục.

### 4.2. `ProcessKey(key rune, mode Mode)` — **HÀM QUAN TRỌNG NHẤT**

- **Input:** `key` — phím người dùng nhấn; `mode`.
- **Logic:**
  1. Chuyển `key` về chữ thường (`lowerKey`), kiểm tra `isUpperCase`.
  2. Nếu `EnglishMode` HOẶC `!CanProcessKey(lowerKey)` → phím không thuộc bảng gõ:
     - Nếu `InReverseOrder`: thêm transformation vào **đầu** `composition`.
     - Ngược lại: thêm vào **cuối**.
  3. Ngược lại: gọi `newComposition` để xử lý tiếng Việt.
- **Ý nghĩa:** Đây là entry point mỗi khi người dùng nhấn một phím. C++ gọi hàm này qua CGO.

### 4.3. `RestoreLastWord(toVietnamese bool)`

- **Input:** `toVietnamese` — nếu true thì chuyển lại tiếng Việt, false thì tách rời.
- **Logic:**
  - Tách âm tiết cuối (`extractLastWord`).
  - Nếu `!toVietnamese`: chuyển âm tiết cuối thành dạng "phím gốc" (breakComposition).
  - Nếu `toVietnamese`: gõ lại âm tiết từ đầu bằng `newComposition`.
- **Ý nghĩa:** Dùng cho tính năng "hoàn tác từ" hoặc chuyển đổi giữa chế độ tiếng Anh/Việt cho từ vừa gõ.

### 4.4. `Reset()`

- **Logic:** Xóa toàn bộ `composition` (gán `nil`).
- **Ý nghĩa:** Dùng khi commit preedit hoặc người dùng nhấn Escape.

### 4.5. `RemoveLastChar(refreshLastToneTarget bool)`

- **Input:** `refreshLastToneTarget` — có cần tính lại vị trí dấu thanh sau khi xóa không.
- **Logic:**
  1. Tìm transformation APPENDING cuối cùng.
  2. Nếu không tìm thấy → return.
  3. Nếu phím đó không thuộc bảng gõ → chỉ cắt bớt 1 phần tử cuối.
  4. Ngược lại: tách âm tiết cuối, lọc bỏ transformation cuối và các transformation tác động lên nó.
  5. Nếu `refreshLastToneTarget` thì tính lại dấu thanh.
  6. Gán lại `composition`.
- **Ý nghĩa:** Xử lý phím Backspace. Không đơn giản là xóa 1 ký tự — phải xóa cả các dấu/mark gắn vào ký tự đó.

## 5. Quan hệ với các file khác

```
bamboo.go
    ├── import: "unicode"
    ├── sử dụng: Rule, InputMethod (từ input_method_def.go)
    ├── sử dụng: Flatten (từ flattener.go)
    ├── sử dụng: findTarget, canProcessKey, extractLastWord,
    │             extractLastSyllable, extractLastWordWithPunctuationMarks,
    │             generateTransformations, generateFallbackTransformations,
    │             refreshLastToneTarget, newAppendingTrans, findLastAppendingTrans,
    │             breakComposition, isValid, regUOhTail
    │             (tất cả từ bamboo_utils.go)
    └── được gọi bởi: C++ qua CGO (qua các hàm export trong bamboo_utils.go)
```

## 6. Lưu ý khi chú thích

- File này **không import `bamboo_utils.go`** — Go tự động link các file cùng package.
- Các hàm trong file này đều có **receiver `*BambooEngine`**, cần chú thích rõ tác động lên `e.composition`.
- Hàm `ProcessKey` và `generateTransformations` là phức tạp nhất — cần chú thích từng nhánh `if`.
- Comment tiếng Anh gốc khá tốt (ví dụ phần `refreshLastToneTarget`), nên giữ lại và bổ sung tiếng Việt.

## 7. Đề xuất chú thích

Thêm block header tiếng Việt ở đầu file, sau header bản quyền. Sau đó chú thích từng hàm theo pattern:

```go
// HàmXYZ: mô tả ngắn
// Input: ...
// Output: ...
// Logic: ...
```
